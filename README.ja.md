# SQLite Archive

XeFM で SQLite データベースを読み取り専用の仮想フォルダーとして閲覧する拡張機能です。

[English README](README.md)

## インストール

XeFM のコマンドラインからインストールします。

```text
xefm ext install github:SinisterSoftware/xefm-sqlite-archive
```

インストール時に表示される確認に従ってください。インストール後、XeFM の **Tools ▸ Reload Configuration** を実行するか、XeFM を再起動すると拡張機能が読み込まれます。SQLite Archive は XeFM 1.13.0 以降に対応し、追加の Python パッケージは必要ありません。

## データベースを開く

1. XeFM で SQLite データベースのファイルがあるフォルダーを開きます。
2. データベースのファイルを選択し、通常のファイルを開く操作（Enter）を行います。
3. 仮想フォルダーに切り替わります。中には `schema.sql` と、テーブルまたはビューごとの CSV ファイルが表示されます。

拡張機能は拡張子ではなく、SQLite ファイルのヘッダーを確認します。そのため、`.db` などの拡張子でも実際の SQLite データベースであれば対象になります。SQLite ファイルでないファイルはこの拡張機能では開かず、XeFM の通常のファイルオープン処理に委ねられます。

## 仮想フォルダーの内容

- **`schema.sql`** — データベース内の SQLite オブジェクトに定義 SQL がある場合、その定義をまとめたファイルです。
- **`<テーブル名>.csv`** — 各テーブルの内容を CSV 形式で出力します。先頭行は列名です。
- **`<ビュー名>.csv`** — 各ビューの内容を CSV 形式で出力します。先頭行は列名です。

CSV は UTF-8 で出力されます。BLOB 値はバイナリそのものではなく、`<BLOB 12 bytes>` のようにサイズを示す文字列として表示されます。ファイル名に使えない文字は `_` に置き換えられます。同じ名前になる項目がある場合は、`(2)` などを付けて名前が重複しないようにします。

各テーブル・ビューから出力する行数は最大 **2,000 行**です。これは各 CSV ごとの上限です。データがそれを超える場合、CSV には先頭側の最大 2,000 行のみが含まれます。取得順序はデータベースの定義に依存し、拡張機能は並べ替えを指定しません。

## SQLite URI で直接開く

SQLite Archive の仮想フォルダーは `sqlite://` URI でも開けます。URI の末尾の `#` はデータベース内の仮想フォルダーのルートを表します。XeFM のパス移動機能で次のような URI を指定してください。

```text
sqlite:///home/alice/data.sqlite#
sqlite://C:/Users/Alice/data.sqlite#
```

パスに空白や `#` など URI で特別な意味を持つ文字が含まれる場合、その文字を URL エスケープしてください。たとえば空白は `%20`、`#` は `%23` と表します。

```text
sqlite://C:/Users/Alice/archive%20%231.sqlite#
```

仮想フォルダー内の `schema.sql` や CSV は通常の仮想ファイルとして閲覧できます。データベースの実ファイルを別の場所へコピーしたり、データベース内の項目を書き換えたりする機能ではありません。

## アクション

この拡張機能は `sqlite_archive.open` アクションを提供します。XeFM のコマンドパレットでアクション名を検索して実行すると、現在のペインで選択中の SQLite ファイルを仮想フォルダーとして開きます。フォルダーが選択されている場合や、選択項目が SQLite ファイルでない場合は何も開きません。

任意で `~/.xefm/config.py` の `KEY_BINDINGS` にキーを割り当てられます。たとえば次の設定は `Ctrl-Shift-S` に割り当てます。

```python
KEY_BINDINGS = {
    'sqlite_archive.open': ['Ctrl-Shift-S'],
}
```

既存の `KEY_BINDINGS` がある場合は、その辞書に項目を追加してください。キー割り当ては任意で、設定しなくてもアクションはコマンドパレットから実行できます。キーの競合や利用可能なキーは、XeFM のキーマップと設定によって異なります。

他の XeFM 拡張機能からは、アクション名が登録されているか `ctx.action_names()` で確認し、`ctx.invoke("sqlite_archive.open")` で実行できます。

## 読み取り専用と注意事項

- データベースは SQLite の読み取り専用モードで開かれます。仮想フォルダーとその中のファイルも読み取り専用で、書き込みやデータベースの変更はできません。
- CSV は各テーブル・ビューにつき最大 2,000 行です。全件のエクスポートが必要な場合は SQLite 用の別のツールを使用してください。
- BLOB はサイズ表示に置き換えられ、CSV にバイナリ内容は保存されません。
- SQLite の問い合わせでエラーが発生した場合、その項目の CSV にエラー内容が出力されることがあります。
- データベースの内容を変更した場合は、仮想フォルダーを開き直してください。拡張機能はデータベースの更新時刻とサイズを使って、生成した一覧をプロセス内でキャッシュします。

## トラブルシューティング

- **ファイルを開いても仮想フォルダーにならない:** ファイルが実際の SQLite データベースか確認してください。この拡張機能は `.db` などの拡張子だけでは判定しません。また、他の拡張機能が `file_open` イベントを処理している場合、イベントフックの競合で SQLite Archive の自動オープン処理が呼び出されないことがあります。その場合はコマンドパレットから `sqlite_archive.open` を実行してください。
- **URI を直接開けない:** URI が `sqlite://` で始まり、実在するデータベースのパスと `#` を含むことを確認してください。URI 特殊文字は URL エスケープしてください。
- **CSV にすべての行がない:** 仕様上、CSV への出力は各テーブル・ビュー最大 2,000 行です。
- **内容が更新されない:** 仮想フォルダーをいったん離れて開き直してください。キャッシュの更新判定はデータベースの更新時刻とファイルサイズに基づきます。
